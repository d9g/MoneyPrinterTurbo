## 二、审计发现

### P0 严重
无。

### P1 重要

#### P1-01: `_xor_decrypt` 变量遮蔽 (lyrics_parser.py 行105)
```python
def _xor_decrypt(data: bytes, key: bytes = b"") -> bytes:
    ...
    return bytes(b ^ key[i % len(key)] for i, b in enumerate(data))
```
`b` 在列表推导中遮蔽了外层 `data: bytes` 的 `b`（虽然 data 不是命名为 b，但 `bytes(b ^ ...)` 中的 `b` 是 int 类型，不是 bytes 类型，语义混淆）。实际运行不影响（因为 `b` 只在推导作用域内），但代码可读性差，容易误读。

**修复建议**: 将 `b` 改为 `byte_val`。

#### P1-02: `acquire_lock` 线程锁跨线程失效 (intent_repository.py 行265)
```python
def acquire_lock(self, signature: str) -> threading.Lock:
    if not hasattr(_intent_locks, "locks"):
        _intent_locks.locks = {}
    if signature not in _intent_locks.locks:
        _intent_locks.locks[signature] = threading.Lock()
    return _intent_locks.locks[signature]
```
`_intent_locks = threading.local()`，意味着每个线程有自己的锁字典。线程A创建的锁，线程B看不到，**跨线程并发锁完全失效**。

**修复建议**: 改用普通 `dict` + 全局 `threading.Lock()` 保护字典访问，或用 `concurrent.futures` 的去重机制。

#### P1-03: `analyze_audio` 二次预处理 (mv.py 行218)
```python
features_obj = analyze_audio(str(audio_path))  # 内部已 preprocess_audio
# ...
y, sr = preprocess_audio(str(audio_path))  # 又调了一次！
```
`analyze_audio` 内部已经调了 `preprocess_audio`，但 `mv.py` 又调了一次，重复加载音频文件。对于大文件（几十MB的FLAC），这会**多花几秒到十几秒**。

**修复建议**: `analyze_audio` 返回 `y, sr` 或在 features 中缓存。

### P2 建议

#### P2-01: `except without logger` 108处
app 目录下 89 处 `except Exception`，其中 108 处 except 块接下来的3行内没有 logger 调用。异常被静默吞掉。

#### P2-02: f-string SQL 误报
检测到6处 f-string SQL，但实际是 logger 语句和 UI key，不是 SQL 查询。**无真实风险**。

#### P2-03: `_file_hash` 用 MD5
`analyzer.py` 用 MD5 做文件哈希缓存 key。虽然这里不涉及安全，但 MD5 有碰撞风险，可能导致缓存错误。建议用 `hashlib.sha256`。

#### P2-04: QRC 解密尝试多个硬编码 key
`lyrics_parser._xor_decrypt` 中硬编码了4个 key 尝试解密。这些 key 来源不明，且 `b""` 空 key 会导致 `len(key)` 为 0，触发 `ZeroDivisionError`。

**修复建议**: 空 key 时跳过 XOR，直接返回原文。

#### P2-05: `get_latest` 查视图 vs `get_latest_by_signature` 查主表
`get_latest` 查 `mv_intent_latest` 视图（按 audio_id 分区），`get_latest_by_signature` 查主表（按 signature 排序）。注释说视图跨 audio_id 失效，但视图本身只按 audio_id PARTITION，设计上没问题——只是用途不同。

#### P2-06: `mv_nightly.py` 无 SSL 验证控制
`requests.post` / `requests.get` 没有显式设置 `verify=True`。虽然默认验证，但如果全局 `REQUESTS_CA_BUNDLE` 被篡改，可能绕过。

#### P2-07: `_save_upload` 文件名安全
```python
safe_name = Path((file.filename or "").strip()).name
```
用 `Path.name` 提取文件名是好的，但 `file.filename` 来自 HTTP 请求，应该额外验证长度和字符。
